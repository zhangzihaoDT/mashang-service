核心变化

V2 将搜索管线从固定模板编排，重构为证据驱动的 Agent 闭环。核心区别：

维度 V1 (旧基线) V2 (新基线)
停止条件 固定模板全部执行完毕即结束 三层证据判断：confirmed / fallback / hard_limit
Query 生成 brand_scout → brand_refine → brand_deep 固定 staged 模板 初始模板 → gap_analyzer 识别缺口 → query_rewriter 动态生成
Profile 控制固定的 Query 数量 控制最大资源边界 + 可接受证据等级
信源策略 按层级分类（tier_1 ~ tier_5） 增加共享起源检测 + 信源类型多样性检查
证据模型 无显式证据评估 独立来源计数 / 官方源计数 / 字段覆盖率 / 高风险 Claim 追踪

管线架构

搜索 → 信息缺口
识别 → 搜索结果
评价 → 动态 Query
改写 → 证据充分性
判断 → 不充分 ↻ 继续 → 充分 ✓ 停止

max_rounds / max_queries / max_provider_calls 仅为安全上限，
真正的完成条件：现有证据是否足以支持一个明确、可审计的回答。

三层停止策略

按优先级顺序评估——满足任意一级即停止：

① confirmed
conclusion: confirmed
independent_sources ≥ 2
official_sources ≥ 1
fields_coverage ≥ 80%
unresolved_high_risk_claims = 0
② fallback
conclusion: probable
independent_sources ≥ 3
source_tier_types ≥ 2
shared_origin_ratio ≤ 50%
allowed: media / dealer / social
fields_coverage ≥ 70%
unresolved_high_risk_claims = 0
③ hard_limit
conclusion: insufficient_evidence
max_rounds exceeded
max_queries exceeded
max_provider_calls exceeded

Profile 不再决定「必须执行多少条 Query」，而是控制「最多花多少资源」和「什么级别的证据可以停止」。

关键设计决策

1. 正常停止（confirmed）

官方源 + 多独立源 + 字段覆盖达标 + 无高风险未解决 Claim。结论可输出为 confirmed。

2. 降级停止（fallback）

当事件本身只出现在非官方渠道（经销商、社交、媒体互证）时允许降级。增加两个防护：

  • min_source_tier_types ≥ 2 — 避免全部来自同一类别
  • max_shared_origin_ratio ≤ 50% — 避免多家媒体转载同一稿件被计为独立来源

结论输出为 probable。

3. 强制终止（hard_limit）

达到资源上限时，返回 insufficient_evidence，不强撑 confirmed 结论。

4. 缺口驱动改写

每轮搜索后生成结构化 gap（answered_fields / missing_fields / unresolved_claims / next_search_objectives），再由 gap 生成下一轮 Query。每轮 Query 不同、针对性强，而非套固定模板。
