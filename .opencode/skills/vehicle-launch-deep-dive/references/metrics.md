# 指标口径与计算

所有口径以 `shared/schema/business_definition.json` 与既有算子（`utils/monitors/*`）为准；本文只记录**研究层**的推导与约束。

## 一、窗口推导

```
T0        = business_definition.time_periods.{gen}.end      # 上市日，业务定义
as_of     = 用户指定的 T−1（最后完整观察日）
N         = (as_of − T0).days + 1
第 d 天    = T0 + (d−1)
窗口       = [T0, T0+N)  左闭右开
```

规则：

1. 三个代际都用**自身上市后前 N 天**，历史数据更多也不扩窗。
2. 若某对标代际在 `as_of` 时可用天数 < N → 取共同可用天数，并在报告写 `window_capped` 与原因。
3. 缺失日期**不补零、不插值**；曲线在该点断开并说明。
4. 预售池可用各自完整预售期，但**转化结果**必须截止到 D_N。

## 二、零售口径

```python
retail = (
    order_type == "用户车"
    & ~order_type.isin(NON_RETAIL)
    & ~flag_test_orders(df)          # 总部主理店 + 非 18 位身份证
    & (store_name != "总部主理店")     # 整店剔除，避免内测/自营混入
)
locks = retail & lock_time.notna()
```

- `NON_RETAIL`：试驾车 / 大客户 / 员工 / 集团员工 / 经销商员工 / 享道 / 仅批售 / 项目 / 展车 / 海外。
- **小订池口径**允许 `order_type` 为空（否则池子会被清空，空白通常是小订阶段未回填），其余同零售口径。
- 过滤前后必须能对账：报告附录给出「原始行数 / 零售保留 / 各代际剔除量」。

## 三、锁单来源三分（互斥）

小订（意向金）在**上市日 24:00 停收**，因此：

| 类别 | 判定 |
|---|---|
| 预售小订转锁 | `intention_payment_time < T0` |
| 上市当日新增小订转锁 | `T0 ≤ intention_payment_time < T0+1d` |
| 直接锁单 | `intention_payment_time` 为空 |
| 口径外残余 | `intention_payment_time ≥ T0+1d`（各代际 2–4 单，单列不并入） |

三项之和必须等于窗口锁单总数，不一致即为 bug。

## 四、差异指标

```
Δ_b(d)        = cum_main(d) − cum_b(d)
边际差异(d)    = Δ_b(d) − Δ_b(d−1)
相对差         = Δ_b(N) / cum_b(N)
```

- 同时给**绝对差**与**相对差**；只有相对差会让读者忽略体量。
- 判定「差距何时形成」用边际差异的绝对值排序，不看符号。

## 五、分解公式

**预售二元分解**

```
Δ预锁 = (P₁ − P₀)·r₀ + P₁·(r₁ − r₀)
        池规模效应        转化率效应
P = 预售池总量，r = 池内已转锁比例
```

**区域分解（辅助，不默认展示）**

```
Δ区域 = (T₁ − T₀)·s₀,区域 + T₁·(s₁,区域 − s₀,区域)
        规模效应            结构效应（Σ = 0）
```

> 主表用**绝对差额** `主车单量 − 对标单量`；结构效应只在需要归因时作为辅表，避免把占比差误读成销量差。

**网络分解**

```
Δ锁单 = (S₁ − S₀)·p₀ + S₁·(p₁ − p₀)
S = 有效锁单门店数，p = 单店锁单
```

**渠道（省级）分解**：同上，按门店所在省份求和应等于全国差额。

## 六、客群口径

| 维度 | 取值 |
|---|---|
| 性别 | `order_gender = 女` 占比 |
| 年龄 | **车主年龄均值**（`owner_age.mean()`，保留 1 位）；不再并列中位数与购车人年龄 |
| 城市线级 | `city_to_tier_label` 四档：一线 / 新一线 / 二线 / 三线及以下 |
| 省份 | 上牌省份（`license_city → CITY_TO_PROVINCE`） |
| 下沉程度 | **看三线及以下占比**，不看一线占比 |

结构距离（可选）：`TVD = 0.5·Σ|p − q|`，用于说明「同档后人群是否更接近」。

## 七、产品口径

- 版本/电量：优先业务映射（如 CM3 的 Pro Max / Max / Ultra = 93 / 76 / 103 kWh），
  字符串规则（`battery_capacity_logic`）可能误判，**必须以业务确认值为准**并在报告注明。
- 座椅/颜色/选装：一律用 `config_attribute` 的 `Attribute` / `value` 原文；
  跨代际只有字面完全相同的取值才算同口径，命名不同要显式标注。
- 配置组合占比：`P(座椅) × P(电量)` 可复算；与订单实际联合分布对比，偏离 >1pp 说明两维不独立。

## 八、订单质量

- 必须用**事件时间点对点重建**（`*_refund_time`、`*_approve_time`、`deposit_*`），不能用当前快照。
- 退订时间在数据中是日期粒度（多为 00:00），只能按日归集，不能解读为某一时刻的批量操作。

## 九、增长动能

```
封盘池 P   = 预售池 + 上市当日新增小订
已锁 / 已退 = 截至 D_N 的事件计数
剩余       = P − 已锁 − 已退
锁/退比     = 已锁 / 已退
日均锁 / 日均退 = (D2–D_N 合计) / (N−1)
```

- 剩余池潜力用「按当前结构可再释放多少」的**区间**，不给单点预测。
- 验证判据写清楚：锁/退比阈值、退订高峰阈值、剩余率阈值。
