# 稳定方法

正式流程只有：定义与快照核验 → PASS 能力计划 → Gate A → 计算 → Findings → Gate B → 内存渲染 → Gate C → 交付。
不再使用四幕十问、启发式章节排序、固定经营判断或动态下钻作为正式流程。

- 所有对标各自独立，不合并平均，不只用第一对标推断“全部对标”。
- 只描述数值、方向、时间窗口及算术差额；分解不等同于机制解释。
- Q3 在单日窗口跳过；其他必要前提失败则阻断，不静默删除失败检查。
- 待转化和剩余池已证明旧算法错误；质量审计仍记录锁退重叠，旧池恒等式校验保留并要求独立互斥证据。不能把可复算的错误公式当准确证据。
- 探索与正式能力分开；探索产物不能被报告渲染器自动加载。新增能力须另行验收更新白名单，不在本轮引入框架。

能力状态和适用条件见 [verified-capabilities.md](verified-capabilities.md)。
