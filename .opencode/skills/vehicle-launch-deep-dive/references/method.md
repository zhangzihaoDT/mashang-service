# 研究方法：四幕十问与分析树

## 一、为什么是「先发现差异，再找解释」

上市研究的常见失败是把报告写成「数据集说明」：五个数据集五章，每章都在描述，但读者读不到差别在哪。
正确顺序是：

```
订单 → 找到最大差异 → 提出解释假设 → 用其他数据验证/证伪 → 标注仍无法解释的部分
```

数据不足时允许「留白」，但必须写明缺什么数据可以补齐，而不是用相关性硬凑因果。

## 二、四幕十问（框架，不是模板）

### 第一幕：卖得怎么样

| 问题 | 判断标准 | 典型输出 |
|---|---|---|
| Q1 同期水平 | 累计锁单 vs 两个对标，差值与相对差 | 累计曲线（实线窗口 + 虚线参考） |
| Q2 差异从哪天形成 | 边际差额序列，哪一天贡献最大 | 边际差额表 / 差额分解 |
| Q3 动能强弱 | 日增、D1 占比、D2–DN 日均、衰减速度 | 日增柱状图 |

**第一幕只回答「差多少、何时形成」，不解释原因。**

### 第二幕：差异为什么出现

| 问题 | 判断标准 | 典型输出 |
|---|---|---|
| Q4 预售规模 vs 转化效率 | 二元分解：池规模效应 + 转化率效应 | 预售池表 + 分解 |
| Q5 上市后直接需求能否接替 | 来源三分（预售 / 上市当日新增 / 直锁） | 100% 堆积条 + 三分表 |

判断规则：
- 若 `预售差` 占差额主体 → 问题在上游蓄客或预售期长度；
- 若 `上市当日新增小订` 明显强于对标 → 上市动作有效，短板在预售；
- 若 `直锁` 占比异常 → 先查下单流程差异（历史代际可能允许跳过小订），不要读作需求强弱。

### 第三幕：差异发生在哪里

| 问题 | 判断标准 | 典型输出 |
|---|---|---|
| Q6 区域贡献 | 省级绝对差额（按主车体量取前 N）+ 城市 Top | 省份表（in-cell bar）+ 城市表 |
| Q7 网络规模 vs 单店产能 | 门店数效应 + 单店产出效应 | 双柱图 + 分解表 |
| Q8 产品与客群 | 版本/电量/座椅/颜色/选装 + 性别/年龄/线级/省份 | 配置结构表 + 客群矩阵 |

Q8 建议拆成三问：
1. **谁在买**（客群骨架）
2. **选什么**（产品结构）
3. **能解释什么**（用差异矩阵与细分对比判断解释力）

### 第四幕：意味着什么

| 问题 | 判断标准 | 典型输出 |
|---|---|---|
| Q9 订单质量 | 退订、大定退款、交付兑现（点对点重建） | 质量表 + 风险项 |
| Q10 后续动能 | 封盘池 → 流出速度（锁/退比）→ 剩余池潜力 | 池消耗图 + 情景区间 |

Q10 只用「当前池 + 速度」推演，**不给预测值**，给区间与验证判据。

## 三、问题裁剪规则

- 两问回答同一件事 → 合并（如「差异从哪天形成」已被 Q1 的边际差额覆盖时，可并入 Q1）。
- 某问在本次数据下无法回答 → 明确写「数据不足 + 缺什么」，保留编号但不写结论。
- 研究发现引出新问题 → 可新增子问（如「同档客群」「六座对比」），但必须挂靠在四幕之下，不新开章节。
- 篇幅按解释力分配，不按问题数量平均。

## 四、动态追问（专题）触发条件

| 触发信号 | 下钻方向 | 需要的额外数据 |
|---|---|---|
| 某省差额最大 | 门店数、单店产出、线索、城市结构 | `store_daily_leads.csv`、门店主数据 |
| 省份出现正增长 | 同店口径对比线索与锁单，区分「需求强」与「承接强」 | 线索表（按门店→省映射） |
| 版本缺口明显 | 按电量段对齐拆解差额 | 版本→电量映射 |
| 同档仍落后 | 控制电量后比客群/配置 | `config_attribute.parquet` |
| 某配置差异大 | 交叉验证（价格、线级、座椅） | `invoice_amount` |
| 竞争格局存疑 | 上市周 vs 预售周 PK 次数与反向排名 | 竞争 PK CSV |

每个专题必须写清：**样本量、口径、结论强度**。样本 < 100 单的差异默认视为不稳健。

## 五、结论表达的三分法

每条结论归入以下之一，并在报告中可见：

- **事实**：可由数据直接复算（给公式与口径）。
- **解释**：有分解支撑，能说明机制（给分解结果与份额）。
- **假设**：方向合理但缺数据（给验证方式与所需数据）。

不要用「可能」「或许」把假设写成结论；也不要把解释写成事实。

## 六、v1.2 研究规划前置（Gate A）

研究计划必须在正式计算前完成核验，**不允许「先算再发现不该算」**。

### 计划要写清什么

每个研究问题都要记录：比较对象、指标、数据依赖、计算方法、可比性条件、输出物、不适用时的处置。

### Gate A 判定规则

| 判定 | 触发条件 | 后果 |
|---|---|---|
| PASS | 数据可得、口径可比、样本达标 | 进入正式计算 |
| SKIP | 可选专题不可比（对标缺该电量段 / 缺配置字段 / 样本不足） | 跳过对应区块，写明原因，主流程继续 |
| BLOCK | 关键问题不成立（任一代际窗口锁单 < 30、预售池 < 100 等） | 引擎退出，不产生任何结论 |

### 两条容易踩的线

1. **核验对象必须与实现一致**：同档客群只比「主代际 vs 第一个对标」，就不能拿全部对标去卡可比性，否则会误杀有效分析。
2. **小差额不等于不能算**：差额小的时候要禁用「占比类」指标（贡献占比、占总差额 X%），而不是禁止整个问题；改用差额结构叙述。

### 结论契约（ResearchFindings）

每条结论必须绑定：指标路径、数值、比较对象、方向（领先/落后/持平/前高后低等）、适用边界。
渲染层只消费结论，不得内联「落后四成」这类固定判断——Gate C 会用禁用语与标题匹配做兜底。
