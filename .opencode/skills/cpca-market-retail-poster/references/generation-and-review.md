# 模型调用与验收

## 付费请求前

- Job 校验期次、区间、指标、同比、来源、统计状态和估算标记，写入本次尝试的 `briefing.json`。Skill 使用其中的 `layout` 及固定参考图构造请求。
- `--generate` 使用 OpenCode Console 为 `opencode/gemini-nano-banana-2.1` 公布的原生端点。确认目标部署可使用该 Console 模型和凭证。脚本优先使用环境中的 `OPENCODE_API_KEY`，其次只读 OpenCode 的 `$XDG_CONFIG_HOME/opencode/.env` 或默认 `~/.config/opencode/.env`。凭证不写入产物。参见 [OpenCode 模型目录](https://opencode.ai/docs/console/models/) 和 [Gemini 图像规格](https://ai.google.dev/gemini-api/docs/image-generation)。
- 请求包含真实参考图的 `inlineData` 字节、完整 Prompt、`imageConfig.aspectRatio=3:4`、`imageConfig.imageSize=1K` 和一个候选项。使用固定模型端点，校验返回的 `modelVersion`。聊天工具及 OpenCode 2.4.2 的 stateless 生图接口分别存在默认模型回退或错误后重试路径，正式海报走单次原生请求。
- 客户端在调用前于候选图目录中独占创建 `generation.json`，记录请求 SHA-256、回包模型、用量、费用和失败状态。该目录只有一次提交机会。收到不确定的结果时，由 Job 返回当前状态，重绘须通过 Job 显式授权新编号。

## 视觉核验

用图像查看工具打开实际图片，按任务 Prompt 和 `briefing.json` 逐项查验。必要时放大三张数据卡和页脚。所有项目通过才可将海报交付为验收通过。

| 项目 | 通过条件 |
| --- | --- |
| 数据与区间 | 完整三段期的六项销量和六项同比须全部准确（12/12）。日期条与各卡片分别对照 CPCA 出口对应条目的起止日，重点确认当月累计和当年累计各自的完整日期。核对卡片顺序、千位分隔和同比精度 |
| 标题与固定文字 | CPCA 标识、两行主标题、指标名称、“同比去年同期”、单位“万辆”和数据来源准确 |
| 统计状态 | 日期条或页脚准确标注初步统计状态，估算期段有相邻两期累计数据反推说明 |
| 同比样式 | 负值为绿色向下箭头与负数，正值为红色向上箭头与正数，零为中性色且无箭头 |
| 卡片容器 | 各行使用同一结构。首卡只有一个圆角外框，底边和右边无叠框、双层边框、额外底板或重影 |
| 卡片对齐 | 各行蓝色标签块的宽度、左右边界和圆角一致，各行中间竖向分隔线严格对齐 |
| 指标图标 | 每行使用同款蓝底白色汽车图形及绿底白色叶片图形。完整三段期须六枚全部正确，图标中无“车”“叶”等文字 |
| 画布与风格 | 请求为 3:4、1K，原生 896×1200 达标。沿用原图标题、天际线和白车、蓝白配色、绿色新能源强调色及信息层级 |
| 可读性 | 无多余指标、旧数字、文字乱码、重叠、重影、裁切，缺失字段正确留空或省略 |

通过 Job 的本地 `--review` 入口记录逐项验收结果及失配位置。验收记录随尝试快照保存，失败图保留在 Job 日志目录。
