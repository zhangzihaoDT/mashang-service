# .sav 文件探索性分析研究思路

本文档沉淀针对 `.sav`（SPSS 处理后的数据集）的探索性分析研究范式，覆盖从数据读取到 PPT 输出的完整链路。

> **脚本实现**：`scripts/explore_sav.py` 已按本流水线实现步骤 1-11（读取 → 字典 → 题型识别 → QC → 描述统计 → 配置归因 → 偏好题识别 → 品牌/价位映射 → 差异扫描 → Topic 深挖 → 统计验证），不含 PPT。用法见文末「脚本实现」章节。

## 1. 数据读取（pyreadstat）

- 使用 `pyreadstat.read_sav()` 读取 `.sav` 文件，同时得到 `df`（数据框）与 `meta`（元数据）。
- `meta` 中保留 SPSS 原始信息：`column_names`、`column_labels`（变量标签）、`value_labels`（值标签，即选项文字）、`variable_value_labels`（按变量查询值标签）。
- 注意 `pyreadstat` 默认把带缺失值标签的观测转为 `NaN`（`user_missing=...` 参数可控制），读取时确认缺失处理口径。
- 编码问题：读取含中文标签的 `.sav` 时若出现乱码，可检查 `encoding` 参数或原文件产生的 SPSS 版本。

## 2. 变量字典

- 从 `meta` 构建变量字典：变量名 → 变量标签 → 值标签映射 → 数据类型（数值/字符/日期/多选题集合）。
- 变量字典是后续所有步骤的查表基础，先完整生成再开始分析。
- 输出标准字典（CSV/JSON），包含：变量名、标签、类型、取值个数、缺失占比、值标签明细。

## 3. 问卷题型识别

- 根据值标签与列结构判断题型：
  - **单选（单选量表）**：一个变量，值标签为有序或无序类别，如「非常满意~非常不满意」「是/否」。
  - **多选（多选题）**：一组变量构成，命名通常带 `_1/_2/_3` 或 `q5a/q5b...`，值标签为「选中=1 / 未选=0」或二分编码，需按题聚合为集合。
  - **数字填空题**：连续值，如价格、年龄、数量。
  - **量表题（Likert）**：有序类别，如 1-5 分或 1-10 分。
- 题型识别决定后续统计口径：多选按「提及率」，单选按「占比」，量表按「均值/分布」。

## 4. Data QC

- **缺失检查**：逐变量缺失率；高频缺失变量标注并判断是否影响下游分析。
- **异常值检查**：数字题做分布检查（如年龄 > 100、价格极端值），量表题检查是否超出取值范围（如 5 分量表出现 7）。
- **多选题逻辑检查**：同一题的选项是否存在「全选」「全不选」「矛盾选项同选」（如「没买过」与「买了 XX 品牌」同选）。
- **逻辑一致性**：跳转逻辑（如「是否购买 → 未购买者不应填购买品牌题」）、时间先后、总量与分量的加总关系。
- **标签完整性**：值标签缺失或含「其他」时，检查是否存在未映射的原始取值。

## 5. Descriptive Statistics

- **频数分布**：分类题各选项占比，多选题给提及率（百分比基数 = 有效回答人数，非选项数）。
- **集中趋势与离散**：连续题给均值/中位数/标准差/分位数；量表题给均值与 Top-2 Box / Bottom-2 Box。
- **交叉表**：核心人口学变量（性别/年龄/城市/收入）× 关键态度或行为变量。
- **时间/分组视角**：如数据含多个波次或渠道来源，按组对比分布形态。

## 6. 配置归因（config-scan）

对满意度研究（如 APEAL）最值钱的发现常来自"配置有/无"的对比，而不是人群差异。这一步把多选组（配置清单）逐选项当作二分分组，比较**拥有该配置 vs 未拥有**的指标差异。

- **分组**：多选组的每个选项（如「主驾电动记忆座椅」「后排通风」Yes/No）。
- **指标**：默认 APEAL 指数族（可 `--metric` 指定）。
- **输出**：有/无两组的加权均值、差值 Δ、Welch t-test p 值、Cohen's d，按效应量排序。
- **过滤**：`--min-has`（默认 50）排除小样本选项；自动排除 `Other / Don't know / Do not have` 等非业务选项，避免效应量虚高。
- **注意**：有/无配置的满意度差异不等于因果，需结合人群结构（高配车往往更贵/更豪华）谨慎解释。

## 7. 偏好题识别（preference）

识别问卷中的「Most Improved / Love Most」（最需改进 / 最喜欢）类题型，输出各题选项的提及率排序，用于改进优先级洞察。

- **识别规则**：列标签含 `Most Improved` / `Love Most`，且非多选二分选项。
- **输出**：每道偏好题的 Top 5 选项提及率，按有效回答数排序。
- **用途**：区分"用户最在乎的改进项"（如屏幕清晰度、界面设计）与"最爱项"，直接指导产品优先级。

## 8. 品牌/价位映射（camp）

对含品牌与价格字段的问卷，内置**品牌阵营映射 + 价位段分箱**，做竞品结构分析。

- **品牌阵营**：`BRAND_CAMP` 常量按 国际品牌 / 独立造车新势力 / 传统车企新能源子品牌 / 传统自主 四类映射（分析假设，报告中注明）。
- **价位段**：`CN_YNV_07`（元）按 10万以下 / 10-20万 / 20-40万 / 40万以上 分箱。
- **输出**：阵营样本占比、价位段 × 阵营交叉结构、各阵营指标加权均值。
- **注意**：样本结构是抽样占比而非市场份额；"份额变化"类趋势需销量数据。

## 9. 自动扫描差异

- 对全量变量做**差异化扫描**，机器优先找出「哪里值得看」，不靠人肉翻表。
- 常用扫描逻辑：
  - 分组均值/占比差异排序（人口学 × 态度/行为），自动计算组间差异大小。
  - 变量两两相关性 / Cramér's V（分类变量）或 Pearson r（连续/量表），给出相关矩阵 Top 对。
  - 多选题选项之间的共现/互斥关系。
  - 与基准（总体均值、上一波次、行业常识基准）的偏离程度。
- 输出「差异候选清单」：变量对 + 差异方向 + 效应量，按显著程度排序，供人工挑选 Topic。

## 10. 找到值得研究的 Topic

- 从候选清单中挑 Topic 的标准：
  - **差异大且解释上有意义**：不是统计噪声，而是业务上可解释的规律。
  - **可反推行动**：能落到「针对哪类用户、调整什么产品/运营动作」。
  - **跟当前业务问题相关**：优先回答甲方/研究问题中最关心的维度。
- 每个 Topic 给出候选表述，如「一线城市年轻用户对 X 的接受度显著高于其他群体」。
- 这一步产出 3~5 个候选 Topic，避免一次摊开所有差异。

## 11. 针对 Topic 深挖

- 对一个 Topic 做多角度验证，而不是只看一个交叉表：
  - **换个维度看**：除了人口学分组，再看行为/态度/渠道分组是否同样成立。
  - **看内部结构**：该群体内部是否仍有分化（如一线城市内部按收入再分）。
  - **找解释变量**：哪些变量与该差异相关，尝试建立解释路径。
  - **排除替代解释**：是否只是样本量差异、缺失偏倚或第三变量混淆所致。
- 深挖过程中不断记录「证据链」，为后续解释与呈现做准备。

## 12. 统计验证

- 对深挖结论做正式检验，避免凭直觉下结论：
  - **卡方检验**（分类 × 分类）、**t 检验 / ANOVA**（分类 × 连续）、**Mann-Whitney / Kruskal-Wallis**（非正态）。
  - **效应量**：Cramér's V、Cohen's d、η²，避免「显著但无意义」。
  - **多重比较校正**：自动扫描产生的对比数量多，需 FDR（Benjamini-Hochberg）等校正，控制假阳性。
  - **样本量说明**：小样本组标注置信区间或直接降级为定性观察。
- 明确记录每个结论的检验方法、p 值、效应量，写入方法附录。

## 13. 用户 / 产品解释

- 把统计结论翻译成业务语言：
  - **用户侧**：这是哪类用户？他们的特征、动机、使用场景是什么？
  - **产品侧**：数据背后的产品含义（功能点、定价、渠道、内容）是什么？
  - **为什么**：给出机制层面的解释（结合常识、行业背景、问卷题项设计意图），而不是停留在「A 比 B 高」。
- 区分**事实**（统计结果）与**推断**（业务解释），推断部分标注依据与不确定性。
- 每个 Topic 输出一段「数据 → 解释 → 建议」的完整叙述。

## 14. PPT

- 将验证过的 Topic 组织成研究汇报：
  - **结论先行**：每页一个核心结论，标题即结论，图表支撑。
  - **故事线**：研究背景 → 数据说明 → 核心发现（每个 Topic 一页）→ 交叉发现 → 用户画像 → 产品建议 → 附录（方法/变量字典）。
  - **证据链引用**：每页标注数据来源、样本量、检验结果，保证可追溯。
  - **克制呈现**：一页一个观点，图表不堆叠；差异大且重要的放前。
- 输出物建议同时给 PPT 与配套 Excel/CSV 明细，便于复核。

## 通用原则

1. **先字典后分析**：不读变量字典就下结论，大概率看错口径。
2. **QC 不过不下钻**：缺失、异常、逻辑矛盾未澄清前，深挖结论不可靠。
3. **扫描是辅助，判断是核心**：自动扫描只负责「找差异」，选 Topic 与解释依赖业务判断。
4. **每个数字必须可溯源**：数据来源、口径、样本量、统计方法逐项记录。
5. **没有数据支撑的观点不写进结论**：证据不足时明确标注「待验证」。

## 脚本实现

`scripts/explore_sav.py` 实现了步骤 1-12（不含用户/产品解释与 PPT），以子命令形式按流水线分段执行。

```bash
# 1-2. 变量字典 / 问卷题型识别
python scripts/explore_sav.py dict            # 输出 variable_dictionary.json
python scripts/explore_sav.py types           # 输出 variable_types.json

# 3. Data QC
python scripts/explore_sav.py qc              # 缺失/未映射取值/多选矛盾

# 4. 描述统计 (加权 APEAL_WT)
python scripts/explore_sav.py describe        # 数值/量表均值 + 多选提及率

# 5. 配置归因 (多选配置 有/无 × 指标)
python scripts/explore_sav.py config-scan     # 按效应量排序，自动过滤 Other/Don't know
python scripts/explore_sav.py config-scan --min-has 100   # 提高最小样本门槛

# 6. 偏好题识别 (Most Improved / Love Most)
python scripts/explore_sav.py preference      # 各偏好题选项提及率排序

# 7. 品牌/价位映射
python scripts/explore_sav.py camp            # 阵营×价位段结构 + 各阵营指标均值

# 8. 自动扫描差异 (分组 x APEAL 指数族)
python scripts/explore_sav.py scan            # 候选 Topic，按效应量排序
python scripts/explore_sav.py scan --group-by SUPER_SEGMENT_DP CITY_TIER_DP  # 指定分组

# 9-12. Topic 深挖 + 统计验证
python scripts/explore_sav.py topic --group-by GENERATION2 --metric APEAL_Index
python scripts/explore_sav.py topic --group-by CN_INCOME --metric APEAL_Index --pairwise  # 含 Tukey 两两对比
```

- 默认输入 `dataset/24 NEV-APEAL数据片段.sav`，输出 `outputs/sav_apeal/`（可用 `--input` / `--output` 覆盖）。
- `--format csv` 输出结构化 CSV（`--format json` 为默认）。
- 权重列 `APEAL_WT` 用于加权均值/占比；统计检验用原始样本并标注效应量。
- 品牌阵营映射（`BRAND_CAMP`）为分析假设，报告中须注明口径。
- 通用参数 `--series` / `--start-date` 等本脚本暂不支持（问卷截面数据无时间维度）；如需 BEV/PHEV 等子集过滤，先 `--group-by` 扫描后对指定分组做 `topic` 深挖。
