项目名称：面向汽车市场洞察与经营决策的 Agent Harness 智能分析工作台

申报赛道：大数据与智能化

申报人：张梓豪

面向汽车市场洞察与经营决策的 Agent Harness 智能分析工作台

一、项目简介

本项目面向新能源汽车企业在市场洞察、销售运营、产品规划、需求预测和经营复盘中的数据分析需求，构建一个以 Data Agent 为核心的 Agent Harness 智能分析工作台。

项目不是传统 BI 系统，也不是单一聊天机器人，而是一个可被 Agent 驾驶的工程化数据分析环境。系统通过 AGENTS.md、README、业务文档、指标口径、数据资产、脚本工具、测试反馈、评估机制和 outputs 输出空间，将汽车业务分析能力组织为可执行、可追问、可校验、可沉淀的智能工作流。

与传统数据分析平台不同，本项目内置汽车行业核心数据资产，包括乘联会周度市场数据、上险量月度数据、企业私有经营数据库以及企业知识库。Agent 不仅能够访问结构化数据，还能够理解企业内部沉淀的业务规则、产品知识、市场研究报告和经营经验，实现数据与知识的统一调用。

在汽车企业日常经营中，业务团队需要持续关注销量、线索、试驾、锁单、成交、价格、竞品、用户反馈、城市表现、渠道转化等多类数据。但现有分析方式通常依赖人工取数、固定报表和临时专题分析，存在数据口径分散、分析链路较长、追问能力不足、经验难以沉淀等问题。尤其在新车型上市、价格调整、竞品冲击、区域异常波动等场景下，业务人员不仅需要“看到数据”，更需要快速理解“为什么变化”“影响在哪里”“下一步应该关注什么”。

本项目以汽车经营分析为核心场景，将自然语言输入、任务拆解、数据查询、图表生成、预测建模、回测验证和报告输出组织在同一个 Agent Harness 工作环境中。业务人员可以通过 OpenCode CLI 或命令行方式提出分析目标，Agent 根据项目驾驶手册、指标口径和数据结构，自主选择合适的脚本和分析流程，完成从问题理解到结果输出的全过程。

项目采用国产大模型作为核心智能引擎，在保证能力的同时显著降低部署和使用成本。相比传统企业级 AI 方案，本项目能够以极低成本实现大规模业务应用，使 AI 从少数人的试验工具变成全员可用的生产力基础设施。

更重要的是，本项目并不把 AI 定义为一个新的工具，而是将 AI 放到工作流最前端。传统 SaaS 的思维是让人学习工具、操作工具、驱动工具；而 Agent 时代的思维是让 Agent 先完成工作，再由人进行判断和决策。项目希望探索一种新的工作模式：

  • 不是把 AI 放进旧工作流，而是让 Agent 暴露出新的工作流；
  • 不再要求业务人员学习复杂的数据工具，而是直接提出业务目标；
  • 不再由人先分析再让 AI 辅助，而是由 Agent 先完成分析，再由人进行判断；
  • AI 不只是工具，而是企业经营分析流程中的第一执行者。

目前项目已围绕参赛场景形成 6 类可展示能力：

  1. Agent 工作台入口：通过 OpenCode CLI 进入项目，直接以自然语言提出汽车经营分析目标；
  2. Agent Harness 工程结构：通过 AGENTS.md、docs、scripts、tests、eval、outputs 等目录组织 Agent 可驾驶的工程环境；
  3. Agent 执行链路：将用户问题拆解为指标识别、上下文解析、脚本调用、图表生成和报告输出；
  4. 连续多轮追问能力：支持从一次问数下钻到车型、城市、异常识别和日报结论生成；
  5. 预测模型资产沉淀：以 lock_release_curve 等模型方式沉淀线索、锁单和销量预测规律；
  6. 建模回测报告输出：通过 lock_predict_backtest 等方式验证预测模型效果，形成可复盘、可评估的分析报告。

本项目可应用于新能源汽车企业的市场洞察、销售运营、产品规划、渠道管理、用户反馈分析、需求预测和经营管理等场景，具备较强的行业应用价值和推广潜力。

三、项目可行性

1. 业务场景真实明确

新能源汽车行业竞争激烈，产品迭代节奏快，价格变化频繁，用户需求和竞品动态变化明显。企业在日常经营中需要持续回答以下问题：

  • 某车型近期订单、锁单、成交趋势是否异常；
  • 某个城市、大区、渠道或车型配置的表现为什么变化；
  • 线索、试驾、锁单之间的转化关系如何；
  • 新车型上市后，不同版本、价格带和城市层级的用户结构如何变化；
  • 竞品上市或价格调整对本品牌车型是否产生影响；
  • 用户反馈中哪些问题最集中，哪些需求最值得优先改进；
  • 经营复盘报告如何从人工整理转向自动化生成；
  • 预测模型如何通过历史数据进行回测和校验。

这些问题具有高频、复杂、跨数据源、需要连续追问的特征，适合通过 Data Agent 和 Agent Harness 的方式进行系统化解决。

2. 数据基础具备可构建性

项目具备明确的数据基础和数据来源。

项目内置的数据资产包括：

  • 乘联会周度市场数据；
  • 上险量月度数据；
  • 企业销售、线索、订单、锁单、成交等私有经营数据库；
  • 企业产品知识库；
  • 市场研究报告与竞品分析资料；
  • 用户反馈与 VOC 数据库。

项目所需数据类型主要包括：

  • 市场数据：行业销量、品牌销量、车型销量、价格带分布、城市层级表现等；
  • 经营数据：线索、试驾、订单、锁单、成交、退订、交付等；
  • 产品数据：车型、配置、价格、权益、能源类型、座位数、版本结构等；
  • 用户数据：城市、年龄段、渠道来源、兴趣偏好、购车阶段等；
  • 反馈数据：用户 VOC、售后反馈、App 反馈、门店反馈、舆情文本等；
  • 外部数据：竞品上市节奏、市场传播、政策环境、宏观趋势等。

这些数据可以通过数据库、CSV、Parquet、API 或企业数据平台接入。Agent 能够统一访问结构化数据库与非结构化知识库，实现“数据+知识”的联合分析能力。

3. 技术路线清晰

项目采用“Agent 工作台 + Harness 工程环境 + 企业数据库 + 企业知识库 + 分析脚本 + 测试反馈 + 输出沉淀”的技术路线。

Agent Harness 工程结构

第一层是 Agent 工作台入口。项目通过 OpenCode CLI 或命令行方式接收用户目标，使业务问题以自然语言方式进入分析工作流。

第二层是 Harness 工程环境。项目通过 AGENTS.md、README、docs、scripts、tests、eval、outputs 等结构，将 Agent 的行动规则、业务知识、数据口径、工具脚本、测试反馈和结果资产组织在同一个 workspace 中。

第三层是企业数据与知识层。系统统一接入乘联会周度数据库、上险量月度数据库、企业经营数据库以及企业知识库，使 Agent 能够同时理解市场、产品、用户和经营信息。

第四层是 Agent 执行链路。系统根据用户自然语言问题，完成意图识别、时间解析、指标匹配、维度识别、上下文继承、脚本调用、结果校验和分析结论生成。对于复杂问题，系统可拆解为多个子任务，逐步完成分析。

第五层是结果输出与沉淀。系统支持生成表格、图表、Markdown 报告、HTML 报告和回测报告，并将结果沉淀到 outputs/tables、outputs/charts、outputs/reports 等目录中，方便复用、追溯和二次分析。

4. 原型建设具备可操作性

项目已围绕 Agent Harness 的核心能力进行原型建设和场景设计，具备以下可展示能力：

  • 通过 OpenCode CLI 进入项目工作环境；
  • 基于项目 README 和 AGENTS.md 明确 Agent 工作规则；
  • 接入企业数据库和知识库；
  • 支持对用户问题进行多步骤拆解；
  • 支持自然语言问数和连续多轮追问；
  • 支持从车型结构下钻到城市分布、异常识别和日报结论；
  • 支持释放曲线等预测模型的可视化展示；
  • 支持预测模型的历史回测和误差评估；
  • 支持将分析结果沉淀为图表、表格和报告。

项目采用国产大模型方案，部署成本和调用成本远低于传统海外模型方案，具备企业内部规模化推广的现实条件。

5. 风险可控

项目主要风险包括数据口径不一致、自然语言理解错误、模型幻觉、权限安全和业务解释不准确等。针对这些风险，项目采取以下措施：

  • 建立指标字典和数据口径文档，降低口径歧义；
  • 对关键指标采用确定性 SQL 或 Python 脚本计算，降低大模型幻觉风险；
  • 对模型输出增加证据链、数据来源和计算过程说明；
  • 对敏感数据进行脱敏处理；
  • 通过 tests 和 eval 机制对关键分析流程进行验证；
  • 对预测模型进行历史回测，验证模型稳定性和误差水平；
  • 将高频分析场景沉淀为标准工作流，提高系统稳定性和可复用性。

因此，本项目在业务场景、技术实现、数据基础和风险控制方面具备较强可行性。

四、项目创新点

1. 从“AI 问数工具”升级为“Agent Harness 工作环境”

传统 BI 和数据问答工具主要解决“看数据”和“问数据”的问题，但面对复杂业务问题时，仍需要分析师手工拆解、取数、计算和解释。本项目将汽车经营分析能力组织为一个 Agent Harness，使 Agent 不只是回答问题，而是可以读取文档、理解口径、调用脚本、执行分析、校验结果并沉淀输出。

项目入口不是固定网页，而是目标驱动的 Agent 工作台。用户提出业务目标后，Agent 可以在 workspace 中自主选择下一步动作，完成端到端分析任务。

2. AI 不再是工具，而是新的工作流入口

本项目最大的创新之一，是重新定义 AI 在企业中的角色。

传统 SaaS 思维强调“学习工具、使用工具”；而 Agent 思维强调“提出目标、获得结果”。

项目认为：

  • AI 不应该被嵌入旧工作流；
  • Agent 应该创造新的工作流；
  • 不应该让员工学习复杂系统；
  • 应该让 Agent 先完成工作；
  • 人负责判断和决策。

例如过去的流程是：

业务提出需求 → 分析师取数 → 制作报表 → 输出结论 → 管理层决策

而未来的流程是：

业务提出目标 → Agent 自动分析 → Agent 输出报告 → 管理层判断决策

这种模式将显著提升组织效率，并释放业务人员和分析师的创造力。

3. 将汽车业务知识沉淀进 Agent 可驾驶环境

本项目不是通用型问答系统，而是面向汽车行业经营分析场景设计的智能工作台。系统将车型、配置、价格、渠道、城市层级、销售漏斗、用户反馈、竞品关系、预测模型等业务知识结构化沉淀，使 Agent 能够理解汽车行业特有问题。

同时，项目将企业知识库与行业数据库统一纳入 Agent 工作环境，使 Agent 不仅知道数据是什么，还知道业务为什么这样变化。

4. 支持连续多轮追问和上下文继承

当前许多数据分析工具只能完成单次查询。本项目强调多轮追问能力，使用户可以从一个问题自然延伸到下一个问题。

例如：

第一轮：昨天锁单数分车型；

第二轮：那 LS8 的城市分布呢；

第三轮：哪些城市相比近 7 日均值下降明显；

第四轮：生成一段可以放进日报的结论。

在这一过程中，系统需要继承时间、指标、车型、维度、对比基准和输出风格等上下文信息。这种连续追问能力使系统从“单次问数工具”升级为“连续分析助手”。

5. 将确定性计算与国产大模型能力结合

本项目坚持“数据计算确定化、分析解释智能化”的原则。关键指标计算、模型预测和回测评估由 SQL、Python 或规则脚本完成，保证结果准确；国产大模型主要负责自然语言理解、任务拆解、路径选择、结论组织和报告表达。

这种架构兼顾了大模型的交互能力和数据分析的准确性，同时具备低成本、高可控和易推广的优势。

6. 将预测模型沉淀为可复用分析资产

项目不仅支持查询和报表，还将销量预测、锁单释放、线索转化等分析方法沉淀为模型资产。例如，通过 lock_release_curve 表达线索或锁单从初始状态到最终结果的释放规律，通过 lock_predict_backtest 对预测模型进行历史回测，评估误差水平和稳定性。

这使项目具备从“描述过去”走向“预测未来”的能力，能够支撑市场洞察、销量预测、资源配置和经营预警等场景。

7. 强调测试、评估和输出沉淀

本项目通过 tests、eval 和 outputs 机制，将分析过程、模型效果和结果资产持续沉淀。每次分析不仅输出一次性答案，还可以生成表格、图表、报告和回测记录，形成可复用、可追溯、可迭代的分析资产。

这也是 Agent Harness 区别于普通聊天机器人的关键特征：它不是停留在对话层，而是进入工程环境中持续行动、反馈和沉淀。

七、项目市场推广 / 应用价值

1. 提升业务分析效率

传统汽车经营分析往往需要业务人员提出需求、数据分析师取数、制作报表、解释结果，周期较长。本项目可以让业务人员通过自然语言提出目标，由 Agent 自动拆解任务、调用工具、生成图表和报告，缩短从问题提出到获得结论的时间。
